Everything a UR cell exposes, reachable from a laptop — the simulator for the experiments, the same code for the hardware, and every capability on four surfaces at once: MCP for agents, the cockpit for people, a CLI, and a Python library. 02COLD STARTPOWER_OFF → IDLE → RUNNING

Start the simulator

1

Clone and bring it up

You need Docker for the simulator and Python ≥ 3.10 for the toolkit. The first start pulls the URSim image.

> git clone https://github.com/Olympus-Controls/UR-utils && cd UR-utils
> docker compose up -d            # the e-Series simulator
2

Open the pendant

PolyScope runs over noVNC in your browser:

http://localhost:6080/vnc.html

NOTEConnect via localhost, not the IP the container prints — that address isn't reachable from the host. On Apple Silicon the e-Series image (amd64-only) won't boot under Docker Desktop; run the PolyScope X sim natively instead: HOST_ARCH=arm64 make simx-up.

3

Wake the robot

Set up the environment with uv and cold-start the controller — power on, then release the brakes:

> uv sync                         # or: pip install .
> uv run urctl bring-up           # POWER_OFF → IDLE → RUNNING
> uv run urctl state              # robot state as JSON
03MOTIONENVELOPE → CONTROLLER IK → PRIMARY :30001

Tell it where to go

Every move is checked before it leaves the laptop — joint limits, speed caps, the robot's state — and absolute Cartesian targets are reach-checked by the controller's own inverse kinematics, not a datasheet sphere. Moves hold the socket open until the controller confirms they landed.

# joint space (radians): safe from any pose
> urctl move-joints 0 -1.57 0 -1.57 0 0

# nudge the tool +50 mm along base +Y
> urctl move-tcp 0 0.05 0 0 0 0 --relative

# everything about the robot, as JSON
> urctl rtde-state --deep
> urctl snapshot

# validate + audit, send nothing
> urctl --dry-run move-joints 99 0 0 0 0 0
from urctl import Robot, RobotConfig

with Robot(RobotConfig(host="10.0.0.5")) as robot:
    robot.bring_up()
    robot.move_joints([0, -1.0, 1.2, -1.8, -1.57, 0])
    print(robot.rtde_state(deep=True))

SINGULARITYA movel from a near-singular pose protective-stops the arm (C154A0) — the default startup pose and the all-zero elbow are both traps. movej to a bent-elbow pose first; urctl bring-up clears a latched stop. To move a lot, stream one trajectory rather than looping single moves.

04AGENT LINKMCP · STDIO

Hand it to an agent

The CLI, the cockpit and the MCP server sit on the same Robot, so an agent gets exactly the tools a person does — schema-validated, safety-enveloped, audited. Pure stdlib; there is no SDK to install.

{ "mcpServers": {
    "ur": { "command": "urctl-mcp",
            "args": ["--host", "10.0.0.5"] } } }
# the same registry for any other framework
> urctl tools
> urctl call get_state --json '{}'

perception-mcp (see .mcp.json) adds the camera and cell tools — locate, segment, snapshot, calibrate, doctor — by proxying the running cockpit, since one process owns the USB camera.

05THE PILOT'S SEATD435 · UR3E · HAND-E

See what it sees. Send it there.

A RealSense D435 on a printed flange bracket, a laptop as the brain, and a cockpit that looks like the scan above: the wrist feed as a CRT, the depth as a point cloud in the robot's base frame, a light column over every object it finds, and a teletype that narrates what the arm is about to do. The approach is measured from the fingertips, not the flange, and the controller's IK decides what's in reach.

# no camera? the same cockpit on a synthetic scene
> uv run perception --fake gui

# a real cell: pre-flight, then the cockpit
> uv run perception --cell ur3 doctor
> uv run perception --cell ur3 gui
# survey, fit each block's top, pick it, set it back
> uv run perception pick-cycle

# four big buttons and a STOP, for an audience
> uv run perception gui --demo

Hand-eye calibration is touch-and-click (or mark-less: the arm orbits a block and clicks every view itself). First picks ran on a UR3e with a Robotiq Hand-E on 2026-09-25. The full walkthrough, with a dated field log, is the pilot's-seat page.

06REAL HARDWARESAME CODE · ONE FLAG

Point it at a real robot

Nothing is hard-wired to localhost — it's only the default. Pass --host or set the environment, and the same commands drive a physical controller.

> urctl --host 10.0.0.5 state
> UR_HOST=10.0.0.5 urctl bring-up
> UR_PLATFORM=polyscopex UR_ROBOT_API_PORT=8000 urctl state   # PolyScope X
VariableDefaultMeaning
UR_HOSTlocalhostController host or IP
UR_DASH_PORT29999Dashboard server
UR_PRIMARY_PORT30001Primary client (URScript runs here)
UR_TIMEOUT_S10Socket timeout, seconds
UR_PLATFORMe-seriespolyscopex swaps Dashboard for the REST Robot-API
UR_ROBOT_MODELprobedSizes the fallback reach cap (UR3e … UR30)
UR_AUDIT_LOGunsetAppend one JSON line per action

REMOTEOn a real e-Series, motion over Primary needs the pendant's top-right indicator on Remote. In Local, moves return ok:false with no violation and the arm doesn't move — and there's no network way to flip it.

BACKPLANEThese ports are unauthenticated on real hardware. Keep the controller on an isolated network: the client-side envelope is a guard, not a substitute for the controller's own safety configuration. Credentials come from your environment (.env), never from this repo.

07PROGRAM LIBRARYprograms/ · 8 ENTRIES

Things it already knows

Ready-to-run samples: load any from the pendant (urctl load MotionDemo && urctl play) or stream it to Primary.

  • InspectionBotA guided, teach-by-prompt inspection tour: freedrive to each station, answer pass/fail on the pendant.
  • PickPlaceA basic cycle — grasp at one station, carry, release at another, return home.
  • PickAndStackPick three items and stack them at one spot; gripper steps left for you to wire in.
  • AppleStackPoses derived from one top-down photo, with no camera calibration at all.
  • MotionDemoThree joint-space poses with textmsg checkpoints — the end-to-end driver's test program.
  • ElegantDanceEvery joint on its own sinusoid, blended paths; each run is unique.
  • DanceA looping choreography authored as script nodes, the pattern for real-robot cells.
  • NodeTreeDemoA native PolyScope node tree — MoveJ, If, Loop, Set, Popup — built from Python.

Author your own with urctl guided MyProgram --save MyProgram.urp: the robot raises a Yes/No on its own pendant for each step and records only what you approve.
